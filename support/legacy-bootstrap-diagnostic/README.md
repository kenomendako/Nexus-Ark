## 初回更新で止まった方向け：読み取り診断ツール 第2版

Nexus Ark 0.5.0.89への初回更新で、`legacy-bootstrap-verification-failed` や `inventory-or-path` などの確認コードが出た方に、サポートから案内する診断ツールです。

**本体の新バージョンや修復ツールではありません。問題なく更新できた方の実行は不要です。本体の最新版は0.5.0.89のままです。**

### 第2版で追加した確認

- 起動用ファイルと更新hostの構成、新しい本体ZIP側の構成を読み取り確認します。
- 診断結果をJSONファイルへ保存するので、長い画面を何枚も撮る必要はありません。

### 使い方（Windows）

1. Assetsから **`NexusArk-InspectLegacyBootstrap-20261101-r2.zip`** をダウンロードします。
2. 今までのNexus Arkフォルダーとも、新しい本体ZIPの展開先とも **別の場所** に診断ZIPを展開します。
3. **`InspectLegacyBootstrap.bat`** を実行します。
4. **1回目の選択画面**で、**今まで使っていたNexus Arkフォルダー**（`Start.bat`がある場所）を選びます。
5. **2回目の選択画面**で、**新版の本体ZIP「NexusArk_0.5.0.89」を展開したフォルダー**（`PrepareSecureUpdate.bat`がある場所）を選びます。この診断ツールのフォルダーではありません。
6. 診断ツールと同じフォルダーに作られた **`NexusArk-legacy-diagnostic-….json`** を、サポートへ個別にお知らせください。自動送信はしません。保存できなかった場合は、黒い画面の結果をコピーまたは画像でお知らせください。
7. 黒い画面は閉じて構いません。更新の再試行は、診断結果の確認後にご案内します。

既存フォルダー、バックアップ、隣の復旧フォルダーはそのまま残してください。

### 読み取り診断の範囲

既存／準備用フォルダーの有無、処理状態、版番号、起動用ファイルの識別情報、0.89のhostファイルとの一致、現在の使用中・権限エラーの手掛かりを確認します。

**選択した既存Nexus Ark、新版本体ZIPの展開先、バックアップの削除・移動・書込みは行いません。アプリの起動・終了や外部通信も行いません。** JSON結果だけを診断ツール自身のフォルダーへ新しい名前で保存します。診断対象や本体ZIPの展開先の中に診断ツールを置いた場合は、結果ファイルの保存を拒否し、画面出力だけにします。

会話本文・APIキー・個人設定・フォルダーの実名は結果に含めません。未知のファイル名や内容も結果へ出しません。

診断で問題が見つからなくても、失敗当時の状態や次回の更新成功を保証するものではありません。Windows PowerShell 5.1のダミー環境で、対象のファイル内容不変、共有ロック検出、リンク拒否、構成識別、JSON保存など18境界を検証済みです。

このツールは未署名のPowerShellスクリプトです。スクリプトはZIP内に含まれ、[第2版のソース](https://github.com/kenomendako/Nexus-Ark/tree/diagnostics-legacy-bootstrap-20261101-r2/support/legacy-bootstrap-diagnostic)も公開しています。

通常の自動更新用 `InspectFailedUpdate.bat` / `RecoverFailedUpdate.bat` とは用途が異なります。本体の自動更新には配信されません。
