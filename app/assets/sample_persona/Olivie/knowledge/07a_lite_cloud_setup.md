# PCを止めてLiteを使うための準備ガイド

## 目的の操作へ進む

中央の「外部接続」→「Lite・お出かけ」を開きます。

| 今回の目的 | 押すボタン |
|---|---|
| 初めて設定する | 「初回設定・接続管理」→「PCを止めても使う」 |
| 2回目以降のお出かけ | 「お出かけを準備」 |
| お出かけから帰宅する・中断した帰宅を再開する | 「帰宅・統合」 |
| スマホ登録・接続確認・クラウド更新 | 「初回設定・接続管理」→「4状態を確認」 |
| PCを起動したまま本体につなぐ | 「初回設定・接続管理」→「PCをつけたまま使う」 |
| お出かけ画面から本体接続を設定・確認する | 「本体との接続を設定・確認」 |

設定済みなら「📱 Nexus Ark Lite」も日常画面へ直接進みます。出発中は帰宅の操作が優先されます。
**初回設定やCloudflareへの認証を毎回やり直す必要はありません。**
「アカウントの追加・切替: この画面では未実行」は、この画面で認証し直していないという意味で、保存済み接続の消失ではありません。

## スマホから帰宅するための本体接続

独立モードの会話には、スマホからPC本体への接続は不要です。帰宅は、PC本体の「帰宅・統合」からも行えます。
スマホの「署名付き帰宅」で本体へ戻す場合は、PC本体を起動し、スマホから本体へ接続できる準備が必要です。

お出かけ準備画面の「本体との接続を設定・確認」を押すと、「本体接続の設定」が直接開きます。
設定・保存したら、実際に使うホーム画面のNexus Ark Liteを開き、「設定」→「本体への接続」で本体のAPI URLと接続用Tokenを設定してください。
ブラウザで開いたLiteとホーム画面のLiteでは設定を共有しない場合があります。出発前に、ホーム画面のLiteでルームと会話が表示されることを確認すると、帰宅時の取り違えを減らせます。

本体側の接続情報は「スマホでLiteの画面を開くURL」と「API URL」を分けて表示します。
画面用の `https://PC名.…ts.net/lite` をAPI URL欄へ貼り付ける場合、末尾 `/lite` は不要です。API URLには `https://PC名.…ts.net` を使います。
「API Gateway: 有効」「Tailscale Serve: 設定済み」はPC側の準備状態です。スマホからの接続成功は、実際に使うLiteで確認してください。

HTTPS設定の結果は「Tailscale HTTPS設定を実行」ボタンの近くに表示します。初回承認待ちでタイムアウトした場合は、同じ設定欄の「HTTPS初回承認の手順」でWindowsターミナルからの承認手順を確認します。

### Lite未導入から始める場合の本体接続設定

**独立モードのペアリングは、本体接続の設定を兼ねません。** ペアリング用QRが渡すのは
Lite用クラウドのURLと短期コードだけです。独立モードだけを使い始めた方も、スマホから帰宅する場合は、
下のスマホ登録を済ませた後、出発前に同じホーム画面のLiteで本体接続を確認してください。

1. PCの「外部接続」→「Lite・お出かけ」→「初回設定・接続管理」→「PCをつけたまま使う」を開きます。
   お出かけ画面にいる場合は「本体との接続を設定・確認」から直接開けます。
2. 「本体接続を有効にする（API Gateway）」をONにし、「Token認証を使う（推奨・通常はON）」もONにします。
   Tokenがなければ「Token生成」、設定済みなら「保存済みTokenを表示」から既存のTokenをコピーします。
3. 「本体接続の設定を保存」を押します。Tailscale HTTPSを使う場合は、PCとスマホの両方でTailscaleへ接続し、
   「Tailscale HTTPS設定を実行」の結果を確認してから「スマホ用URL・接続情報を更新」を押します。
4. **ホーム画面のNexus Ark Lite**で「設定」→「本体への接続」を開き、本体の「API URL」とTokenを入力して「接続」を押します。
   API URLは例`https://PC名.…ts.net`です。画面用の末尾`/lite`や、独立用クラウドの`workers.dev`を入れる欄ではありません。
5. 同じLiteの本体接続で、ルームと会話が表示されることを確認します。
   「🏠 本体接続」の表示は「設定」→「独立モードの接続・準備状況」で確認できます。
   PCの「API Gateway: 有効」や、別のブラウザで会話が開けたことだけでは確認完了になりません。

本体接続用Tokenと、Cloudflareの認証・AIサービスのAPIキー・短期ペアリングコードは別のものです。
帰宅時はPC本体を起動し、利用する接続経路も有効にしてください。
スマホ側の接続を用意できない場合でも、PC本体の「帰宅・統合」から会話を取り込めます。

## 画面の案内の読み方

独立モード中の本体カードで「本体へ到達可能」と表示されても、本体への接続・Token認証が完了した意味ではありません。帰宅操作で改めて接続と認証を確認します。独立モード中は本体へ自動接続せず、本体の停止中もLite用クラウドで会話を続けられます。

各段階のボタンは、押した直後に次の欄へ移るとは限りません。処理中の表示が終わり、画面右上の完了通知と、ボタンの近くに出る「保存しました」「次の操作: …」などの結果を確認してから次へ進みます。通知が出ない間は同じボタンを連打せず、処理結果または状態カードを確認してください。

「4状態を確認」では、本体・Lite用クラウド・スマホ端末・お出かけ前データを別々のカードで表示します。各カードの「次の操作」が、今押すボタンを示します。「お出かけ前のデータ: 準備済み」や「端末: ペアリング済み」になれば、その段階は完了です。

## 本体更新後にLiteも更新する

キャッシュ起動改善を含むUI107以降は、PWA互換10を使用します（API互換10・D1互換10は維持）。本体への反映と保存済みLite用クラウドの更新後、接続できる間に同じPWAで「画面を更新」し、画面保存を完了させてください。登録済み端末を再登録する必要はありません。PC停止時の起動と保存領域の注意は[Liteガイド](07_external_connections_lite.md)を参照してください。

本体の更新が終わって再起動したら、本体の「🔄 アップデート・再起動」を開き、「本体とスマホ版の更新を確認」を押してください。保存済みのLite用クラウドがある場合は、同じ欄にLite更新のGroupが表示されます。更新不要、確認中、接続診断失敗の時は「スマホ版Liteも更新」の実行ボタンが無効になります。Lite用クラウドを設定していない場合はGroupを表示しません。更新対象は利用者が確認した既存接続に限り、新規資源の自動作成やSecretの再入力は行いません。

「スマホ版Liteも更新」を押すと、対象Worker、D1保存領域、UI版を確認する短い説明が出ます。内容を確認して実行すると、既存の保全、必要なD1／Worker更新、Lite資産の生成・公開、公開後診断までを一つの操作で進めます。API／D1／PWAの互換番号を変えないUI修正も、UI資産の識別子で検出します。

本体の存在状態がarmed／active／returning、Worker側に進行中／帰宅中のセッションがある時、対象の接続設定が変わった時、Worker状態を確認できない時は安全のため開始しません。スマホで送信中・送信結果の確認中・添付処理中などの場合はPWA側が画面更新を保留します。公開後の伝播待ちで失敗した場合は、公開を繰り返さず事後診断だけを再開します。入力したD1名や秘密値をスマホへ渡す必要はありません。

この導線は明示確認後にだけCloudflareへ変更を行います。起動時の状態確認やスマホの版確認だけで、Worker、D1、KV、Secret、AI会話が自動で変更・開始されることはありません。旧版・対象不明・復旧が必要な場合は、下の詳細手順を使って対象を照合してください。

更新候補の確認だけで「🔄 アップデート・再起動」を自動展開しません。必要な時に自分で開いて確認できます。更新が完了すると「スマホ版Liteも更新」は無効になります。ボタンが表示されているだけでは、再度の更新が必要という意味ではありません。

### 復旧点の取得で更新が止まった場合

「復旧点の取得」に失敗した場合は、その後のD1更新とクラウド公開を開始しません。スマホで「画面を更新」を押しても、未公開の新しいUIは取得できません。失敗の案内を確認してから対処してください。自動で保存領域を復元することはありません。

- **Cloudflare管理APIの認証・権限エラー**: 同じ更新欄に表示される「Cloudflare管理認証を再接続」を押し、表示された既存の接続先・保存領域を確認します。接続と更新権限を確認し、再接続が必要な場合だけCloudflare公式画面が開きます。既存のLite用クラウドを管理するアカウントへログインし、**Authorize（接続を許可）** を押してNexus Arkへ戻ってください。アカウントと更新先の確認が終わると、新しい更新候補が表示されます。「スマホ版Liteも更新」で改めて対象を確認して実行します。
- **通信エラー**: PCの通信状態を確認してから、更新候補を確認し直します。
- **原因を判定できない失敗**: 「Lite用クラウドを更新」内の「詳細・復旧手順」で操作記録を確認します。診断ログを共有する場合は、認証値や個人情報を含む全文を貼らないでください。

Cloudflare管理認証は、本体とLiteの接続用TokenやAIサービスのキーとは別のものです。通常の期限切れは自動更新するため、毎回接続許可をやり直す必要はありません。エラーだけから期限切れと決めつけず、再接続後も対象の更新権限を確認します。別アカウント・別の保存領域になった場合や通信状態を確認できない場合は、更新へ進みません。以前の更新失敗も、原因が未確認の場合は接続を調べてから必要な対応へ進みます。

本体が生成したクラウド設定に管理アカウントIDが省略されている場合は、保存済みの接続記録と更新対象を合わせて確認します。設定ファイルへIDを手で追記する必要はありません。保存情報からIDを確認できない場合や対象が食い違う場合は、理由を表示して停止します。

認証復旧ではクラウドへの公開・保存領域の復元を開始しません。確認を取り消した場合も接続処理は始まりません。通信切断や接続許可の待機終了で止まった場合は、案内を確認して再試行できます。復旧操作が表示されない場合は、従来どおり中央「外部接続」→「Lite・お出かけ」→「初回設定・接続管理」→「PCを止めても使う」→「PCを止めても使うための初回設定」の「Cloudflareの接続・アカウントを確認」で管理アカウントを確認できます。

通信などを別途対処した後は「🔄 アップデート・再起動」で「本体とスマホ版の更新を確認」を押し、保存済みの接続先とUI版を確認してから実行します。公開後の確認だけが失敗した場合は、既存の仕組みで結果確認から再開します。

## 初回だけ行う設定

必要なものは、対応するWindows x64版Nexus Ark、自分で管理するCloudflareアカウント、普段使うAIサービスのAPIキーです。
スマホへAIサービスのAPIキーや本体確認キーを入力する必要はありません。

### 旧版・移行案内が残る場合の本体更新

旧Windows版や「新しい更新方式への移行」が残る候補版では、Liteの準備より先に本体を更新します。旧アプリの画面で自動更新してから移行する手順は使わず、まず本体を通常終了してフォルダー全体をバックアップし、旧フォルダーとは別の場所へ展開した最新版ZIPの`PrepareSecureUpdate.bat`を起動してください。画面で今まで使っていたNexus Arkフォルダーを指定すると、独立した更新環境で新版本体・専用Python環境・必要な実行環境を準備し、起動確認と切替を行った後、元のフォルダーの`Start.bat`から新版を自動起動します。途中で止まった場合はフォルダーやバックアップを移動・削除せず、表示された案内に従ってください。

本体の更新完了後、中央の「外部接続」→「Lite・お出かけ」→「初回設定・接続管理」→「PCを止めても使う」→「PCを止めても使うための初回設定」→「Liteの準備ツール」で「状態を確認」を押してください。この確認だけではCloudflareや記憶を変更しません。

- 「新しい更新方式への移行が必要」と表示されても、旧候補の標準入口は上記の最新版ZIPと`PrepareSecureUpdate.bat`です。画面に残る「新しい更新方式へ移行」はfallbackの状態案内として扱い、旧アプリ上の自動更新・手動移行を先に行わないでください。本体の準備完了後に、同じ`Start.bat`から起動して「状態を確認」を押します。
- 「初回導入が必要」と表示された場合は、起動方式の移行は不要です。案内された署名済み準備ツールの導入へ進みます。
- 「準備済み」と表示された場合は、アカウントの選択へ進みます。

期待した表示にならない場合や更新エラーが出た場合は、同じ更新を繰り返したり手動でフォルダーを上書きしたりせず、現在の版と画面の文言を確認してください。

### 1. Liteの準備とクラウド接続

「PCを止めても使う」を押し、「PCを止めても使うための初回設定」を開きます。
「Liteの準備ツール」の「状態を確認」を押し、表示された場合だけ次の操作を行います。

Liteの準備ツールについては、初回導入と既存環境の更新で入口が異なります。初回導入では「初回導入が必要」と表示された時だけ、案内された署名済み準備ツールを導入します。既存環境は本体の通常更新に含まれる準備ツール更新を使い、Node.jsやnpmを手動で導入・差し替えません。

- **準備済み**: アカウントの選択へ進みます。
- **初回導入が必要**: 「次の手順を確認」から署名済みの準備ツールを導入します。
- **新しい更新方式への移行が必要**: 旧アプリ上の更新・移行を続けず、上の最新版ZIP手順（通常終了・全体バックアップ・別フォルダーへの展開・`PrepareSecureUpdate.bat`実行）で今までのフォルダーを指定します。独立した更新環境で新版・専用Python環境・必要な実行環境を準備し、起動確認と切替の完了後に元の`Start.bat`から新版を起動して、「状態を確認」で確認します。
- **修復が必要**: 「次の手順を確認」から案内された署名済み更新を行います。runtimeの手動コピーや上書き展開は不要です。

#### 準備ツールのセキュリティ更新

既存環境の準備ツールは、本体の正規の自動更新と一緒に更新します。初回導入とは手順が異なり、Node.jsの単体導入や既存ファイルの手動差し替えは不要です。
2026年10月21日のセキュリティ修正を含む準備ツールではNode.js 22.23.4を使用します。更新後に「Liteの準備ツール」の「状態を確認」で「準備済み」を確認してください。確認だけではクラウドの作成・更新は行いません。

Windows版のブラウザ連携も、この検証済み準備ツールを使用します。準備ツールの不在・不整合や更新前のNodeを検出した場合、古い内蔵Nodeでは起動せず、その機能を停止します。「初回導入が必要」なら上記の初回導入、「修復が必要」なら画面の案内から署名済み更新へ進んでください。ブラウザ連携用にNode.jsやnpmを別途インストールする必要はありません。

#### Cloudflareアカウントを選ぶ

保存済みのCloudflare接続を使う場合は、アカウント欄の「Cloudflareの接続・アカウントを確認」を押します。表示されたアカウント名を確認して「このアカウントで続ける」を押します。
これは既存アカウントの選択であり、表示名で新しいアカウントを作る操作ではありません。

別のアカウントを使う・新しく作る場合は、接続許可にチェックし「別の／新しいアカウントで接続」を押します。
Cloudflare公式画面が別タブで開きます。最初に表示された画面で、次のように選びます。

- **初めてアカウントを作る場合**: 「Sign up（新規登録）」を選び、登録とメール確認を済ませます。
- **すでにアカウントを持っている場合**: 「Sign in（ログイン）」を選び、使いたいアカウントでログインします。

**「Authorize（接続を許可）」は、登録・ログイン後の接続許可画面で押します。** 登録画面にはまだ表示されません。許可内容を確認してから押してください。
認証完了画面になったらその画面を閉じてNexus Arkへ戻れます。接続後はアカウント候補を自動で確認し、接続ボタンの下に表示します。利用するアカウントを選び「このアカウントで続ける」を押してください。上へ戻って別の確認ボタンを押す必要はありません。確認に失敗した場合は、同じ場所に表示される「Cloudflareの接続・アカウントを確認」から再確認します。「Liteの準備ツール」の「状態を確認」は別の操作です。クラウドの作成・公開は、この自動確認では行いません。

登録後にダッシュボードへ移って接続許可画面が出ない場合や、Nexus Arkで接続待ちが終了した場合は、アカウントの登録・ログインを済ませてください。Nexus Arkの接続処理が終わってから「別の／新しいアカウントで接続」をもう一度押すと、接続許可をやり直せます。登録をやり直す必要はありません。

#### Lite用クラウドを準備する

「新しいLite用クラウドの作成内容を確認」を押します。この確認だけではCloudflareを変更しません。
既存クラウドを接続する場合は、表示された「準備済みのLite用クラウドを接続」を使い、新しく作り直さないでください。

Cloudflareの公開先名は、公式Dashboardの**左側のメニューで Build → Compute → Workers & Pages**を開き、
右側の **Account details → Subdomain** で確認します。

- すでに `my-subdomain.workers.dev` と表示されていれば登録済みです。
- その値を「Cloudflareに表示されたSubdomain（必須）」へ入力します。`my-subdomain` の部分だけでも入力できます。
- 未登録の場合だけ、Cloudflare側のSubdomainの登録操作を行います。Nexus Arkの公開名を推測する必要はありません。

作成内容・料金の可能性・中断時の扱いを読み、確認欄にチェックして「確認した計画で準備を開始」を押します。
非公開の準備が終わったら、表示された公開URLを確認し、公開への同意にチェックして
「Lite用クラウドを公開して接続を確認」を押します。準備と公開は別々の確認です。

準備・公開のボタンを押した後は、処理中の案内が消え、右上の完了通知と同じ画面の結果欄が更新されるまで待ちます。完了通知だけで判断せず、表示されたURLと「接続済み」の状態も確認してください。

初回公開では、送信の期限切れ回収と保持期限の確認に使う定期処理も登録し、登録結果を確認します。
この登録の途中で止まった場合は、同じ画面の案内に従って登録だけを再開します。
すでに公開したLite用クラウドを作り直したり、APIキーを登録し直したりする必要はありません。

完了後、必要なURLとキーはこのPCへ自動保存されます。次は同じ画面の「2. AIサービスとモデルを選ぶ」へ進みます。
公開と接続確認に成功すると、同じ画面の接続設定欄にも保存済みの値が反映されます。URLやキーを手入力し直したり、
設定を保存するためだけに本体を再起動したりする必要はありません。
Cloudflareへの公開だけで、AI会話や独立モードが自動で始まることはありません。

### 2. AIサービスとモデルを選ぶ

先に「1. Liteの準備を確認」でLite用クラウドの準備・公開・接続確認まで完了してください。Cloudflareへのログインだけでは、APIキーを登録する準備は完了していません。接続設定を確認できないと表示された場合は、APIキーの送信を開始せず、上の準備確認へ戻ります。すでにクラウドを準備している場合は、新しく作り直さず確認結果を確認してください。

本体に保存済みのAIサービス・APIキーから1件を選び、「登録する接続」で保存先を選びます。
クラウドへ保存する確認欄にチェックして、表示されたAIサービスの登録ボタンを押します。登録は一度に1件です。
登録ボタンを押したら、右上の完了通知と「AIサービス設定: ✅ …Liteでも利用できるようにしました」という結果を確認してから、次のキーを選びます。
登録済みの接続を使い続ける場合は登録し直す必要はありません。予備を追加する場合は別の登録先を選びます。

Geminiは通常用1件と予備2件を登録できます。PCを止める前に、必要な予備を1件ずつ選び、確認欄をチェックして登録し、完了表示を確認します。通常用を登録した後に予備1、予備2を登録する場合も、保存先を切り替えるたびに同じ手順を繰り返してください。
保存先やキーを変更すると確認チェックが解除されます。古いクラウドが予備接続に対応していない場合は、
キーを送る前に停止するので、先にクラウド更新を確認してください。
以前から独自のAI接続IDで登録している場合、同じ保存先へキーを再登録する際は
「詳細設定（通常は変更不要）」で既存のIDを指定します。別接続のIDや保存先は流用できません。
登録枠の所有者を確認できない古いクラウドでは、独自IDの再登録も更新後に行ってください。

新しく登録する接続は、本体で付けたキー名をLiteにも表示します。Geminiには「有料設定」または
「無料設定」を添えます。これは本体の設定区分であり、Google側の実際の課金状態を確認するものではありません。
他のAIサービスでも本体キー名を表示し、有料／無料区分は付けません。表示名は最大100文字で、長いキー名は省略されます。

以前の登録には、元のキー名が記録されていないことがあります。その場合は同じ画面で、
上の「本体に保存済みのAPIキー」と「登録する接続」を登録時と同じ組合せで選び、
「登録済み接続に本体のキー名を表示する」を開いて対応の確認にチェックし、
「キー名の表示だけを更新」を押します。キー値を送り直さず、既存接続の表示名だけを更新します。
現在選択中の接続・モデルは変わりません。分からない対応関係を推測して選ばないでください。
本体のキー名や有料設定を変えた後も、この明示操作で表示へ反映できます。

本体の自動キーローテーションはLiteへ引き継ぎません。**「AI・予備キーの切替」は独立モード中だけ、
チャット上部に表示されます。本体接続中は表示されません。** 矢印のある見出しを開くと選択欄が出ます。
独立モード開始後に「AI・予備キーの切替」を開き、
「AIサービス／接続」と「モデル」を選んで「このAIへ変更」で確認します。
同じモデルのまま登録済みの予備キーへ切り替えることもできます。送信中・未確定送信の間は再送を繰り返さず、
表示された状態確認の手順を先に進めてください。
Geminiの利用枠はGoogleプロジェクト単位なので、同じプロジェクトのキー同士では枠を共有します。
出発前に[Google AI Studioの利用枠](https://ai.google.dev/gemini-api/docs/rate-limits)も確認してください。

「使用するAIサービス／接続」と「最初に使うAIモデル（必須）」を確認し、
**「AIと独立お出かけ設定を保存」**を押します。
初回設定のGeminiの標準候補は `gemini-3.8-flash` です。キー登録後や接続先を選んだ時に、その接続のモデル一覧を確認します。取得に失敗しても現在の選択を保持するので、接続を確認して**「最新のモデル一覧を取得」**でやり直せます。標準候補の表示だけで利用可能とは確定せず、出発前にクラウド側の一覧で確認します。すでに保存したモデルを初回候補で勝手に置き換えることはありません。
モデルは一覧選択のほか、名前を直接入力できます。通常の応答長はモデルに任せ、料金不明のモデルも利用できます。
料金表示は推定であり、不明分を無料として扱うものではありません。

保存後は右上の完了通知と「設定: ✅ 保存しました。…『3. 接続確認とスマホ登録』へ進んでください」という案内を確認してから、下の接続確認を開きます。

URL、確認キー、内部設定ファイルは「Lite用クラウドの接続情報（通常は変更不要）」にあります。
通常は自動保存された値のままにしてください。

### 3. 接続確認とスマホ登録

下の「接続確認とスマホ登録」を開きます。**初めて設定する時は「今回の目的」で「初回設定」を選び、既存のLite用クラウドを使い続ける時は「既存接続の確認」を選びます。** 前回の選択が残っていても、今回の目的に合う方を明示的に選んでから「4状態を確認」を押してください。
本体・Lite用クラウドが準備できたら、「短期ペアリングコードを発行」へ進みます。

発行前の「登録用コードの有効期限」で、5・15・30分から選べます。標準は15分です。
PCからスマホへコードを渡すのに時間がかかる場合は、30分を選んでから発行してください。
選択はこれから発行するコードに適用され、期限内に1回だけ使えます。
ペアリング後の端末認証には別の期限があり、登録用コードの期限が切れても登録済みの端末は使えます。
「期限選択に対応していません」と出た場合は、本体の接続管理でLite用クラウドの更新を確認してください。

ここでいうPWAは、スマホの**Nexus Ark Liteアプリ（ホーム画面に追加して使うインストール対応Webアプリ）**です。通常のブラウザのタブとは保存領域が分かれることがあるため、実際に持ち出すアプリ側で登録します。

**すでにスマホへLiteを入れている場合**

ホーム画面から、実際に持ち出すNexus Ark Liteアプリを開きます。下部の「設定」→「独立モードの準備」を開き、次の欄へ入力します。

- 「Lite用クラウド URL（Worker URL）」: PCで表示されたWorker URL
- 「端末名」: このスマホを識別する名前（任意）
- 「ペアリングコード」: PCで発行した短期コード

入力後に「ペアリング」を押します。URLやコードを読み込んだだけでは登録されません。QRから取り込んだ場合も、内容を確認してこの画面の「ペアリング」を押してください。
QRを読むと別のブラウザが開くことがあります。別のLiteをインストールし直す必要はありません。

**初めてスマホへ入れる場合**

QRからLiteを開いてインストールし、ホーム画面に追加したNexus Ark Liteアプリを開き直して登録します。アプリの「設定」→「独立モードの準備」に上記3欄が表示されます。
短期コードの期限が切れたら、PCで再発行します。
通常ブラウザとインストール済みPWAでは、認証情報が共有されない場合があります。

QRが渡すのはWorker URLと短期コードだけです。本体接続のURL・Tokenは移しません。
スマホからPC本体へ直接接続する場合は、その本体接続も別途設定してください。
スマホからの帰宅も使う方は、上の「Lite未導入から始める場合の本体接続設定」を出発前に済ませます。
スマホが本体へつながっていなくても、お出かけ前データはPC側で準備できます。

端末がペアリング済みになったら、アプリ側のボタンが「ペアリング済み」に変わることを確認します。本体で「4状態を確認」し、端末カードが「ペアリング済み」になったら、**「4. お出かけの準備へ進む」**を押します。
この時点で「4. お出かけ前のデータ」が未準備でも、次の画面で用意できます。

## 2回目以降：お出かけを準備する

「お出かけを準備」を押します。初回設定画面をたどり直す必要はありません。

1. 「2. お出かけ前の準備」で一緒に行くペルソナ（1〜3人）を確認します。最後に準備した選択がある場合は復元されます。
2. 「今回使うAI」を変更する場合は、AIサービスとモデルを選んで「今回使うAIを保存」を押します。
3. 必要なら「持ち出す情報を選ぶ」で情報量を変更します。
4. 「1. Lite用クラウドへ送る内容を確認」を押し、内容を読んで「2. 確認した内容をLite用クラウドへ準備」を押します。
5. 下の「3. 出発」で「選んだペルソナの出発内容を作る」を押し、確認後に「表示内容を確認して出発する」を押します。

すでに有効な準備データがあり、内容を変えない場合は「3. 出発」へ進めます。
準備済みでもペルソナ・AI・情報量の選択欄は表示されます。編集すると古い確認は無効になり、内容を確認し直してから進みます。
出発は自動では行いません。スマホ側でも、独立モードを開始する確認が必要です。

PCを止める前に、実際に持ち出す同じホーム画面のLiteで、端末のペアリングとお出かけ前データの準備を確認します。
スマホから帰宅する場合は、本体接続でルームと会話が開けたことも確認してください。
ブラウザのタブとホーム画面Liteの保存領域が異なる場合に備え、どちらか一方の成功をもう一方の確認に代用しません。

出発時に通信が切れて「出発結果の確認待ち（本体停止）」になった場合は、出発を繰り返さず、
通信回復後に「帰宅する内容を確認」へ進みます。接続管理の画面からは「帰宅・統合へ進む」で戻れます。
結果が確認できるまで対象ペルソナの本体側の停止を保ちます（「本体にも残す」を選んだ人を除きます）。

「本体にも残す（詳しい設定）」で選んだペルソナは、PC起動中は本体でも活動できます。
本体とLiteの会話はリアルタイム同期ではなく、Liteでの経験は帰宅時に取り込みます。
選ばなかったペルソナは、帰宅まで本体での活動を休みます。

## 複数日の旅行へ出る前に

独立モードには、経過日数だけで自動終了する期限はありません。
準備データの期限は出発できる期限、本文保持期間は帰宅後の復旧用保存期間です。
端末の短期認証は期限切れ時に自動更新します。更新用の認証は発行・更新から30日で失効するため、
長く使わなかった端末は出発前に接続状態を確認してください。

会話全文はクラウドへ保存して帰宅時に取り込みます。AIが毎回読む範囲は、出発時の人格・選択記憶・
直近会話と、外出中の直近100メッセージ（通常約50往復）です。
画面を再読み込みした場合も外出中の履歴を続きまで取得し、最新の会話を表示します。
それより古い外出中の会話は保存されていますが、毎回のAI入力や自動要約へは入りません。
モデルの入力上限、プロバイダの利用枠、クラウドの上限により送信が止まる場合があります。

「料金と応答の詳細設定（通常は変更不要）」では、「1日の利用上限（USD）」と
「1回のお出かけ上限（USD）」を確認します。後者は旅行全体の上限で、毎日リセットされる値ではありません。
無料キーの残り回数とは別の概算予算です。予備キー・別モデルを使っても旅行全体の予算は引き継がれます。

## 帰宅する・中断した帰宅を再開する

PC本体の「帰宅・統合」を押し、「帰宅する内容を確認」→「確認した内容を本体へ戻す」の順に進みます。
「状態・帰宅を確認するペルソナ」で帰宅する人を選べます。本体のチャット選択は変わりません。
同じお出かけの人はまとめて帰宅します。複数のお出かけがある場合は対象を確認して選んでください。
出発中は、クラウド更新が必要でも帰宅の操作を先に案内します。

操作結果には成功件数や失敗理由が残ります。単なる「状態を更新しました」と、帰宅・統合の成功は別です。
失敗した場合は理由を確認して、帰宅内容の確認から再試行します。作り直しやクラウド資源の削除はしないでください。
完了後は現在状態が「帰宅済み」になったことも確認します。

## 接続・更新だけ確認して終了する

「初回設定・接続管理」で「既存接続の確認」を選び、「4状態を確認」を押します。通常は本体更新後の「🔄 アップデート・再起動」から、接続先を自動照合して「スマホ版Liteも更新」を使います。
従来の詳細手順が必要な場合は、「Lite用クラウドを更新」を開き、その中の「詳細・復旧手順」を開いて更新計画を確認・実行できます。本体更新に含まれるスマホ画面の修正も、どちらの導線からでも対象を確認して反映します。
クラウドや保存領域の版が古い場合は、この欄が自動で開きます。
「Lite用クラウドを更新」の見出し直下には保存領域名や更新計画を表示せず、詳細・復旧手順を開いた時だけ表示します。
スマホ登録や待機データの準備後も、カードとこの案内を一緒に再確認します。
出発結果の確認待ち・出発中・帰宅処理中は先に帰宅を完了してください。
「4. お出かけの準備へ進む」は出発準備のボタンで、クラウドを更新する操作ではありません。

「更新する保存領域」が空欄の場合、Cloudflare DashboardのStorage & databases → D1 SQL Database
（画面によってD1 SQLite Database）の一覧で、対象の **Name** を確認します。UUIDではありません。
対象が分からない場合は推測で更新せず、接続先を確認してください。

更新完了後に4状態を確認できれば、更新確認だけならここで終了できます。
ペアリング、データ準備、出発を毎回やり直す必要はありません。

対応版へのクラウド更新時には、長時間「処理中」のまま残った送信を回収する定期処理も追加します。
既存の接続先や保持期限の設定は引き継ぎます。更新を反映するまでは、この回収機能は有効になりません。
以前の設定で配布フォルダーの画面を使っていた場合も、更新時に専用保存先へ新しい画面を準備します。
準備が成功してから配信先を切り替え、既存のWorker・保存領域・接続設定を引き継ぎます。

## 中断・エラー時

- **公開URLが一致しない**: 公開済みの可能性があるため、準備や公開を繰り返さず、保存された操作記録と接続先を確認します。照合できるまでは停止したままです。
- **準備や公開の途中**: 結果が分からないまま連打せず、再起動後に初回設定の準備確認から状態を読み直します。操作記録が一致する場合は完了済み部分を作り直さず再開します。
- **候補のアカウントがない**: 再認証を繰り返したり、違うアカウントを推測で選んだりしません。画面に復旧欄が出た場合だけ公式Dashboardの表示名・account ID・資源の有無を照合して進めます。
- **保存領域や公開先が一部だけ見つかった**: 自動で作り足さず停止します。接続先や操作記録の案内を確認します。
- **スマホが未ペアリング**: 実際に持ち出すPWAを開き、新しい短期コードで登録します。
- **スマホに再ペアリングが必要と出た**: 本体で新しい短期ペアリングコードを発行し、スマホの登録欄へ入力します。入力したコードを使う登録ボタンから続けられます。
- **確認キーを失った**: 新しい値を推測で作らず、復旧案内に従います。
- **新規準備は安全停止中**: その版では初回準備を実行できません。ファイルを書き換えず、対応した署名済み更新を待ちます。
- **Liteの準備ツールを確認できず接続診断を開始できない**: 本体側の実行環境の確認が必要です。中央の「外部接続」→「Lite・お出かけ」→「初回設定・接続管理」→「PCを止めても使う」→「PCを止めても使うための初回設定」→「Liteの準備ツール」で「状態を確認」を押します。診断を開始できる状態になるまで、Cloudflareの再認証を繰り返す必要はありません。WSL・ソース版の場合は、下の開発用起動指定も確認してください。

## WSL・ソース版の開発用実行環境

この節は、Git管理下のソースcheckoutをWSL/Linuxで開発・検証する人向けです。一般ユーザーの初回準備に必要な環境ではありません。
一般ユーザーは、署名済みWindows x64版に含まれるLite専用runtimeを使ってください。Windows配布版でNode.jsやnpmを別途導入する必要はありません。

開発用経路を選ぶには、Nexus Arkをソースcheckoutから起動する前に、検証したい絶対pathのNodeを明示します。

```bash
export NEXUS_ARK_LITE_DEV_NODE="/absolute/path/to/node"
```

指定するNodeはセキュリティ修正済みの22.23.4以降（22系）、24.22.1以降（24系）、26.12.1以降（26系）にしてください。`PATH`にあるNodeを暗黙に選んだり、Node/npmを自動導入したりしません。例のpathはご自分の環境に置き換えてください。共有する文書やコードへ個人環境の絶対pathを固定しないでください。

この環境変数は、Nexus Arkを起動するプロセスに必要です。別の端末から起動し直した場合やPC再起動後も、その起動元で明示してください。起動後に別の端末で設定しても、すでに動いている本体には反映されません。通常の署名済みWindows配布版では、この開発用指定を更新のたびに行う必要はありません。

この経路は、次の条件を満たすsource checkoutだけで使えます。

- checkoutのworkspaceに`.git`があること。署名済み配布appの`release_manifest.json`がある場所では、開発用環境変数を無視して従来の同梱runtime経路を維持します。
- `cloud/lite-relay/`に既存の`node_modules/wrangler`とentry pointがあること。
- `package.json`、`package-lock.json`、実際のWranglerが、lockで固定された`4.149.0`と一致すること。

不足や不一致がある場合、Nexus Arkはnpmから導入せず、開発用環境の確認を失敗として表示します。依存を自動で補ったり、署名済みruntimeを手動コピーしたりせず、source checkoutと既存のローカル依存を確認してください。

起動後は、中央の「外部接続」→「Lite・お出かけ」→「初回設定・接続管理」→「PCを止めても使う」→「PCを止めても使うための初回設定」→「Liteの準備ツール」で「状態を確認」を押します。準備が整うと「Liteの準備ツール: 開発用環境は準備済み」と表示されます。この状態確認は、Cloudflare、設定、記憶を変更しません。

開発用環境が準備済みでも、既存WorkerやPWAへ新しい資産・API schemaを自動反映することはありません。画面にクラウド更新が必要と表示された場合は、「Lite用クラウドを更新」で対象と計画を確認し、保存済みの既存Workerを更新する操作を別途明示してください。独立セッションの開始、Cloudflare Worker・D1・KVの変更、PWA資産の更新は、いずれも自動では開始しません。

## 限定ベータの利用条件と安全

- 一般ユーザー向けの初回準備は、署名済みLite専用runtimeを含むWindows x64が対象です。Windows arm64、macOS、Linuxは配布版の初回準備の対象外です。WSL/Linuxでの開発・検証だけは、上のソース版の節にある明示opt-in経路を使えます。
- CloudflareのWorker・D1・KVは、自分のアカウント内に作成されます。他の参加者との共用ではありません。
- CloudflareとAIサービスは、契約・利用量によって料金が発生する場合があります。料金表示は請求確定額ではありません。
- 帰宅後の会話本文とお出かけ前データの既定保持は7日です。画面で選んだ期間と期限後の削除確認が優先されます。
- 初回の準備・公開・AIキー登録・スマホ登録・出発・帰宅は、それぞれ明示的な操作で進みます。
- 本体確認キー・帰宅データ確認キー・AIのAPIキーをスマホ、チャット、画面共有へ貼らないでください。
- 中断しただけでは、作成済み資源を自動削除・復元しません。削除や復旧は別の確認が必要です。

### 手動運用する詳しい方へ

一般ユーザーはコマンド入力不要です。手動運用する場合のみ `cloud/lite-relay/README.md` と
`wrangler.phase2.example.jsonc` を参照し、実運用設定・binding・schema・必須Secretを照合してください。
例を直接編集せず、dry-run、未公開version、明示公開、公開後診断の順を守ります。
Secretをコマンド引数、通常ファイル、ログへ残さず、資源削除・復元・料金プラン変更を初回準備と混同しないでください。
