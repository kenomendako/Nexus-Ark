# トラブルシューティング

よくあるつまずきと確認場所をまとめます。
エラーが出た時は、まず現在のルーム、使っているプロバイダ、APIキー、対象タブを確認してください。
内部ログは中央「デバッグコンソール」で確認できます。

## APIキーを登録したのに会話できない

左サイドバー「⚙️ 設定」→「共通」→「🔑 APIキー / Webhook管理」→「Gemini（AI Studio）」で、キー名と値が保存されているか確認します。
次に「⚡ AIモデルプロバイダ設定（デフォルト）」で、使用するGemini APIキーが選ばれているか確認します。

ルームごとの個別設定を使っている場合は、「⚙️ 設定」→「個別」→「⚡ AIモデルプロバイダ設定（このルーム）」も確認します。
「共通設定に従う」ではなく個別プロバイダを選んでいる場合、そのルーム専用のモデルやキーが使われます。

## Vertex Geminiの接続エラーが出る

個別のプロバイダ設定は、そのルームの応答に適用します。内部処理のGeminiは共通の接続先を使います。
応答だけVertexで試す場合は、共通で「AI Studio（Gemini）」、個別で「Vertex AI（Agent Platform）」を選びます。

新しい診断表示では、取得できたHTTPコード・APIのstatus・エラー種別を表示します。
例えば `HTTP 403 / PERMISSION_DENIED / ClientError` は権限の確認が必要な手掛かりです。
SDKの元の例外本文・URL・キー・送信内容は表示しません。

| 表示 | 確認すること |
| --- | --- |
| HTTP 400 | APIキー、モデル名、入力形式、推論設定などの送信パラメータ。 |
| HTTP 401 | APIキーや認証情報。 |
| HTTP 403 | APIの有効化、利用権限、請求設定。 |
| HTTP 404 | モデルID、接続方式に対応するモデル、リージョン、利用権限。 |
| HTTP 429 | 割当上限や混雑状況。時間を置いてから確認します。 |
| HTTP 5xx | 接続先の一時的な障害の可能性。時間を置いてから確認します。 |
| AuthenticationError | 実行環境の認証情報と権限。 |
| TimeoutError / ConnectionError | ネットワーク、タイムアウト、接続先の稼働状況。 |
| TypeError / ValueError / SDKError | SDKの互換性、送信パラメータ、対応する入力形式。 |

これらは原因を絞るための分類で、特定の設定が誤っていると断定する表示ではありません。
HTTPコードがなく種別だけ表示される場合もあります。
旧表示の「接続設定と認証を確認してください」だけでは、認証不備とモデル側のエラーを判別できません。
問い合わせには新しい診断表示を添え、APIキーや会話本文を貼る必要はありません。

## Vertexで他モデルは動くがArgonだけ404になる

他モデルが同じ接続で応答できた場合、基本の接続・認証は動いています。Argonだけの404は、そのモデルの提供範囲・接続方式・利用権限などを分けて確認します。

2026-10-19時点の[Argon公式ガイド](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-4-argon)にはGoogle Cloud側での提供が記載されています。一方、[Express接続の公式対応モデル一覧](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/start/express-mode/overview#available_models_and_rate_limits_in_express_mode)にはArgonがありません。ただし、一覧にない他モデルの動作報告もあるため、この記載だけで利用不可とは断定できません。

Nexus ArkのVertex「APIキー」方式は、Google Cloud Projectを空欄にするとExpress経路、ProjectとVertex Locationを入力すると指定Project経路です。標準のProject付き接続で利用可能なモデルでも、Expressで利用できるとは限りません。Argonで404が出る場合は、Google Cloud側で応答したProject IDを入力し、まずLocationを`global`にして保存・再試行します。経路が変わることで改善する場合がありますが、モデルの提供範囲・利用権限・リージョン条件によっては404が続くため、必ず成功するとは限りません。ADCを使う場合もArgonの対応リージョン（`global`／`us`／`eu`）、SDK、および送信パラメータの互換性を確認してください。

Argon向け公式ガイドはPythonの`google-genai >= 2.30.1`を案内しています。対応するNexus Ark更新版ではSDK・送信形式を調整しますが、接続方式ごとのモデル開放は変わりません。Projectと`global`を指定しても404が続く場合は、Google Cloud側の同じProject・接続方式での提供範囲、利用権限、リージョンを確認してください。SDK更新だけで解消すると断定せず、キーの削除・再登録を繰り返す必要もありません。

## Gemini会話でResponseの添字エラーが出る

`'Response' object is not subscriptable` が出る場合、Geminiの元のAPIエラーが
ライブラリのエラー処理で隠れている可能性があります。キーや会話データの破損を意味する表示ではありません。
2026-10-08に通常開発版へ反映した修正では、Gemini Flashの単発呼び出しが内部でstreamへ変わる問題に対応しています。
この修正は本体側のため、Lite用クラウドの更新は不要です。

修正後も503（モデルの一時的な混雑）などが出る場合は、少し待って再送するか、利用可能な別モデルを選んでください。
同じ文章の連続送信は避け、前の応答が確定してから再送します。

## 本体の更新確認でエラーが出る

左サイドバーの「🔄 アップデート・再起動」→「本体とスマホ版の更新を確認」で、
「本体の更新を確認できませんでした」（旧表示「✅ 更新確認エラーが発生しました。」）と表示された場合は、
本体の最新版判定が完了していません。
本体の会話や保存データが壊れたことを示す表示ではなく、本体はそのまま利用できます。

更新情報の版番号について説明が出た場合は、保存済みの更新情報と公開先が整合していません。
開発版の保存済み情報が公開版より新しい時などに、古い情報への巻き戻しを防ぐ確認が働きます。
この番号は本体のバージョンやLiteのUI版とは別です。問い合わせには画面の文言とログの例外名を添えてください。

Liteが本体と同じUI版で「スマホ版Liteも更新」ボタンが無効な場合、それはLite側に更新候補がない状態です。
Liteの状態は、同じ欄の「スマホ版Liteの更新」で確認してください。

## 旧Windows版や移行案内が残る版を更新する

公開済みの旧Windows版や「新しい更新方式への移行」が残る候補版では、旧アプリの画面で自動更新してから手動移行する手順を使いません。まず旧Nexus Arkを通常終了し、フォルダー全体のバックアップを作成します。最新版の公式ZIPを旧フォルダーとは別の場所へ展開し、展開先の`PrepareSecureUpdate.bat`をダブルクリックしてください。画面のフォルダー選択で今まで使っていたNexus Arkフォルダーを指定し、旧アプリが完全に終了していることと、全体バックアップを作成済みであることを確認してから続行します。PowerShellのコマンドを手入力する必要はありません。

準備ツールは独立した更新環境で新版本体・専用Python環境・必要な実行環境を準備し、起動確認と切替を行います。切替が完了すると元のフォルダーの`Start.bat`から新版が自動起動します。設定・ルーム・会話を手作業で移す必要はありません。

全体バックアップは省略しないでください。準備に失敗した場合は、旧フォルダー・初回更新用の保管領域・
`update_recovery`・backupを移動／削除せず、画面の案内を確認します。
`UpgradeUpdateSystem.bat`は通常の更新手順ではなく、復旧案内で指定された場合にだけ使います。

初回更新が「安全に切り替えています」で止まる場合は、繰り返し実行せず診断を依頼してください。対応する準備ツールでは、失敗した工程・Windowsエラー番号・復旧状態を「詳細診断」として表示・保存します。案内された読み取り診断ツールで確認できます。古い準備ツールが残していない失敗情報を、後から復元することはできません。

## OneDrive配下やリンクを含む場所で準備が止まる

OneDriveの同期対象や、リンクを含む場所では、更新対象を安全に切り替えられない場合があります。
「同期フォルダーやリンクの属性を検出」または`preparation-linked-path`と表示された場合は、準備を進めず次の手順を確認してください。
同期していない通常のデスクトップもあるため、フォルダー名だけでは判断しません。ダウンロードフォルダーも同期やリンクの設定によっては対象になります。

1. Nexus Arkを通常終了し、**今までのフォルダーを移動・削除せず残します**。
2. OneDrive内にオンライン専用ファイルがある場合は、エクスプローラーで今までのフォルダーを右クリックし、**「このデバイス上で常に保持する」**を選びます。ファイルの取得と同期が完了するまで待ちます。
3. 全体をOneDriveなどの同期対象外の通常フォルダー（例：`C:\NexusArk-Local\NexusArk`）へ**コピー**します。途中で強制終了せず、エラーやコピーし残しがないことを確認してください。
4. 新版ZIPも同期対象外の**別フォルダー**へ展開します。新版の`PrepareSecureUpdate.bat`を開き、3の**コピー先**を指定します。旧環境のPythonをそのまま起動できるとは限らないため、コピーした旧版の`Start.bat`を先に起動しないでください。
5. 更新が完了したら、コピー先から起動した本体の版番号・会話・設定を確認します。以後はそのコピー先が利用場所になります。元のOneDrive内フォルダーは保全用として残してください。

コピーが止まる・エラーが出る・コピー先でも同じ案内になる場合は、強制終了・上書き・属性の手動解除をせずご相談ください。
すでに更新の切り替え失敗や復旧途中の記録がある場合も、先に診断を依頼します。隣の復旧フォルダーやlockを手作業で移動・削除しないでください。
セキュリティソフトやOneDrive全体の保護・同期を無効にする必要はありません。

## 更新後も旧バージョンのままで、PermissionErrorが出た

新版への切り替えが完了していません。更新記録が`rolled_back`なら、更新処理は旧版への復旧完了を記録しています。
同じ失敗を繰り返さないため、再起動や同じ更新ボタンだけでは再試行されない場合があります。
`app.next`・`.venv.next`・`update_recovery`・lock・バックアップを手作業で削除しないでください。

まず、案内された診断ツールの`InspectFailedUpdate.bat`を開き、今までのNexus Arkフォルダーを選びます。
診断結果は本体フォルダーの外へ保存し、配布担当へ伝えてください。本体やlockは変更せず、APIキー・会話本文・絶対パスは診断結果に含めません。

**配布担当から再試行を案内された場合だけ**、対応版の公式ZIPを別の場所へ展開して使います。
Nexus Arkを通常終了し、フォルダー全体のバックアップを保持したうえで、展開先の`RecoverFailedUpdate.bat`から今までのフォルダーを選んでください。
失敗時の記録と準備途中の世代を保管し、現在の会話・設定から更新を準備し直します。準備完了後は元のフォルダーから新版の起動確認を開始します。
起動した本体のバージョンと、従来の会話・設定が保持されていることを確認して初めて更新完了です。
再試行するのは、記録された失敗対象の版です。その後に最新版への更新が案内された場合は、通常の自動更新へ進みます。

途中終了や停止表示が出た場合は、繰り返し実行せず診断を依頼してください。未完了の再試行を示す`retry-pending.json`やlockも削除しません。
ウイルス対策の無効化や管理者実行で解決しようとせず、記録を保持してください。

## 旧Windows更新方式の移行案内が表示される場合

左サイドバー「🔄 アップデート・再起動」に表示される「新しい更新方式へ移行」は、旧更新方式の状態を知らせる補助案内です。旧候補版の標準入口ではないため、このボタンを先に押して旧アプリ内の自動更新や手動移行を始めず、上の「旧Windows版や移行案内が残る版を更新する」の手順で最新版ZIPを別展開し、`PrepareSecureUpdate.bat`から今までのフォルダーを指定してください。

準備中や復旧状態が不明な場合は、本体更新と画面の再起動を止めます。旧フォルダー・バックアップ・準備用フォルダーを移動・削除せず、画面の説明に従ってください。状態が変わらない場合に`UpgradeUpdateSystem.bat`を使うときも、復旧案内の指定に従います。

この表示は独立モードやCloudflareの設定とは別の、本体更新方式に関する補助案内です。再起動前から開いていた画面で表示や操作が合わない場合は、ページを再読み込みしてから確認してください。

## Windowsのブラウザ機能の準備でエラーが出る

Lite独立モードを使わない場合も、左サイドバーの「🔄 アップデート・再起動」→「ブラウザ機能の準備（Windows）」を
利用できます。まず「ブラウザ機能の準備を確認」を押してください。最初に「ブラウザ機能の状態を確認しています。表示まで少しお待ちください。」と表示され、実物の検証後だけ実際のNode版や準備完了が表示されます。初回の準備が必要な場合だけ表示される
「署名済みブラウザ用Nodeを準備」を押すと、現在の本体に対応した実行環境を署名検証して取得します。
準備後に確認ボタンをもう一度押し、「✅ ブラウザ機能の準備が完了しました」と、その下の「Nexus Arkを通常どおりご利用いただけます。」を確認します。

- **「新しい更新方式へ移行」が必要と表示される**: 旧Windows版の本体更新が必要です。先に上記の最新版ZIPを
  旧フォルダーとは別の場所へ展開し、`PrepareSecureUpdate.bat`から今までのフォルダーを指定してください。
  独立した更新環境で新版本体・専用Python環境・必要な実行環境を準備し、起動確認と切替が完了した後、元の
  `Start.bat`から新版を起動してブラウザ機能の状態を確認します。PowerShellを手動で操作する必要はありません。
- **導入済みの実行環境に修復が必要と表示される**: ファイルを手作業で置き換えず、「🔄 アップデート・再起動」から
  本体の署名済み更新を確認してください。更新後に確認ボタンを押し直します。
- **準備に失敗した**: 既存のruntimeは変更されていません。Nexus Arkを再起動して確認し、同じ状態が続く場合は
  本体の署名済み更新を適用してください。

この準備にCloudflareアカウント、AIキー、ペルソナの設定は必要ありません。一般公開版では本番の更新先を使い、
設定ファイルやJSONの更新先を手作業で変更しないでください。

## APIコストが気になる

次を確認してください。

- 「⚙️ 設定」→「共通」→「📊 API使用量の概算」。
- 「⚙️ 設定」→「個別」→「📡 送信コンテキスト設定」→「APIへの履歴送信（短期記憶の長さ）」。
- 中央「自律行動」→「自律行動（このルーム）」→「✨ 自律行動設定（このルーム）」。
- 中央「自律行動」→「自律行動（このルーム）」→「🔬 リサーチ・テーマ（継続調査・このルーム）」。

送信履歴を短くし、自律行動の間隔を長くし、自動リサーチ上限を下げると、呼び出し回数を抑えやすくなります。

## 記憶を思い出してくれない

左サイドバー「⚙️ 設定」→「個別」→「📡 送信コンテキスト設定」→「記憶の想起（長期記憶）を有効化」がONか確認します。

ナレッジに保存した思い出や参考情報も自動参照してほしい場合は、同じ場所の「ナレッジも自動想起に含める（関連時のみ）」もONか確認します。親の「記憶の想起」がOFFの場合、ナレッジの自動検索も行われません。
中央「知識」→「📚 知識ファイル」で知識ファイルの索引が作成済みか確認します。
中央「記憶・ノート」→「記憶」→「🛠️ 記憶のメンテナンス (手動実行)」から、記憶索引や現行ログ索引を更新できます。

Embeddingモデルを変えた後は、古い索引をそのまま使うと検索精度が落ちることがあります。
その場合は「🗑️ 索引を初期化して再構築」を検討してください。

## スマホから開けない

中央「外部接続」→「Lite・お出かけ」→「📱 Nexus Ark Lite」→
「A・すぐ使える『PCをつけたまま使う』」→「本体接続の設定」で、接続が有効か確認します。
「スマホ用URL・接続情報を更新」を押し、「Nexus Ark Lite 接続情報」に表示されるURLを使います。

同じWi-Fiを使う場合は、`127.0.0.1`ではなく画面に自動表示された`192.168...`等のURLをスマホで開きます。
開けない場合はPCとスマホが同じWi-Fiか確認し、Windowsの確認画面でNexus ArkまたはPythonの
「プライベートネットワーク」通信だけを許可してください。公共ネットワークへは許可しないでください。
Tailscaleを使う場合は、PCとスマホの接続状態と、画面のTailscale HTTPS診断を確認してください。
マイクや通知が使えない場合は、HTTPSで開いているか、ブラウザの権限が許可されているか確認します。

## Lite独立モードを開始できない

中央「外部接続」→「Lite・お出かけ」→「📱 Nexus Ark Lite」→「☁️ Lite独立モード」へ進み、
まず「現在の状態に更新」を
押します。本体、Worker、端末、待機snapshotのどこで止まっているかと次の操作が表示されます。この診断は
読み取り専用です。詳細な導入・更新状態が必要な場合は、続いて
「Lite用クラウドを接続・確認（すでに準備済みの方）」→
「詳細・保守（問題がある時だけ）」で「Lite用クラウドを詳しく診断」を押します。

初めてLite用クラウドを準備する方は、「PCを止めても使う」を押し、開いた初回設定の案内に沿って進めてください。
詳しい利用条件は **「PCを止めても使う」の詳しい説明** で確認できます。

- **新規準備ボタンが安全停止している**: 実環境での開放確認前です。Cloudflare上の変更は始まっていません。
  本体接続を利用し、Nexus Arkの更新後にもう一度確認してください。
- **Liteの準備ツールに「修復が必要」と表示される**: 「修復用の更新を確認」を押し、署名済み更新がある時だけ一括修復します。
  更新がなければ、公式配布パッケージを同じ場所へ入れ直します。Node.jsやnpmを別途導入する必要はありません。
- **公開先の初回登録が必要と表示される**: 公式Cloudflare Dashboardで`workers.dev`を一度登録し、
  Dashboardに表示された`workers.dev`の公開名だけを入力します。完全なURLは本体が組み立てるため、アカウント名からURLを推測しないでください。
- **準備中に画面やPCが停止した**: 作成ボタンや公開ボタンを繰り返し押さず、Nexus Arkを再起動して状態を確認します。
  完了済みのものを読み直して次の操作を表示し、確認できない場合は安全停止します。

- `prerequisite_missing`: Liteの準備ツールと同梱relay資源を確認します。runtimeだけを手作業で置き換えません。
- `migration_required`: 画面の安全更新計画を作り、表示されたmigrationをWorker公開より先に適用します。
- `worker_update_required`／`client_update_required`: WorkerとNexus Ark本体の組合せを更新します。
- `active_session_blocked`: 進行中または帰宅途中の旅行を先に完了します。暗黙に削除しません。
- `secret_action_required`: `OWNER_AUTH_TOKEN`、`BUNDLE_SIGNING_KEY`、`STANDBY_ENCRYPTION_KEY`を確認します。
- `maintenance_overdue`: 保持期限previewを確認してから手動掃除を実行します。
- `unreachable`／`unauthorized`／`unknown_schema`: migrationやdeployを試さず、URL、認証、schemaを確認します。

Lite側で「お出かけ前データなし」と表示される場合は、本体接続中に「今の状態をお出かけ前のデータとして準備」を押します。
ただし、接続状態のお出かけ前データが「使用中」なら、準備し直す必要はありません。チャット上部が
「本体接続」のままの場合は、スマホの設定から「独立モードを開く」を押してください。
0.5.0.55のLiteでこの操作が無効な場合は、スマホのアプリ切り替え画面からLiteを閉じ、ホーム画面から
開き直します。「独立モード」になったことを確認してから会話します。再ペアリングや出発のやり直しは不要です。
「再ペアリングが必要」と表示される場合、snapshotがないという意味ではありません。端末認証の期限切れまたは
失効によりsnapshotの有無を確認できない状態です。本体で新しい短期ペアリングコードを発行し、通常ブラウザではなく
実際に持ち出すインストール済みPWA内で再ペアリングしてください。

短期コード発行時のQRを読んでも通常ブラウザが開く端末があります。その画面の「接続状態」で「通常ブラウザ」と
表示される場合はペアリングせず、持ち出すPWAを開いてWorker URLと短期コードを手入力してください。
「QRの短期コードは期限切れ」と表示された場合は、発行時に選んだ有効期限を過ぎています。
本体で新しいコードを発行します。標準は15分です。共有に時間がかかる場合は「登録用コードの有効期限」で30分を選んでから発行してください。
QRを開いただけではペアリングは実行されないため、PWA内で内容を確認して「ペアリング」を押してください。
本体へ接続できないだけでは自動開始しません。「独立モード」を押し、分岐可能性の説明を確認してください。

独立モードで送信に失敗した場合、チャットの「前回の送信でエラーが発生しました」に理由と確認コードを表示します。
この表示は、同じ接続先・お出かけ・ペルソナで開き直しても確認できます。問い合わせには確認コードとHTTP番号だけを
添え、会話本文やAPIキーは送らないでください。「前回の送信を確認」欄がある場合は、結果が確定するまで新しい文を
送らず「送信結果を再確認」を押します。欄がない場合も、返信や履歴を確認できていなければ送信成功とは限りません。
元の文章を急いで再送したり、データを削除・再作成したりせず、表示された理由を確認してください。

## 通知が来ない

左サイドバー「⚙️ 設定」→「共通」→「📢 通知サービス設定」で、アラーム用と通知用のサービスを確認します。
Discord WebhookやPushoverキーは「🔑 APIキー / Webhook管理」で保存します。

中央「自律行動」→「自律行動（このルーム）」→「✨ 自律行動設定（このルーム）」→「🌙 通知禁止時間帯（このルーム）」に入っている時間帯は、通常通知が抑制されます。

## メニューが見つからない

まず、左サイドバー、中央タブ、右サイドバーのどこを探しているか確認します。
左サイドバーは「設定」系、中央タブは会話・記憶・自律行動・外部接続、右サイドバーはプロフィールと情景です。

このガイドで案内しているラベルは、現行の実UIに合わせています。
アップデート後に場所が変わった場合は、中央「デバッグコンソール」ではなく、該当するタブ名やアコーディオン名を優先して探してください。


## ブラウザ連携がセキュリティ更新を求める

Nexus Arkを正規の自動更新で更新してください。Windows版では左サイドバーの「🔄 アップデート・再起動」→
「ブラウザ機能の準備（Windows）」で「ブラウザ機能の準備を確認」を押します。初回の準備が必要な場合だけ表示される
「署名済みブラウザ用Nodeを準備」を押してください。導入済みの実行環境に修復が必要な場合は、
ファイルを手作業で差し替えず、本体の署名済み更新を確認します。詳しい手順は「Windowsのブラウザ機能の準備で
エラーが出る」を参照してください。

ブラウザを使うURL取得、Gemini共有ログの取り込み、X連携、アトリエのプレビューは、検証済みの修正版Nodeが使えない場合は停止します。URL取得では通常の本文取得を引き続き試します。設定を回避したり、環境変数・Nodeファイルの手動差し替えで進めたりせず、準備ツールの案内を確認してください。


## 証明書のセキュリティ更新と旧版からの更新準備

Nexus Arkは、通信相手の確認に使う証明書と更新用ツールを修正版へ更新しています。旧Windows版から更新する場合は、まず旧アプリを通常終了してフォルダー全体をバックアップし、最新版の公式配布ZIPを別の場所へ展開してください。展開先の`PrepareSecureUpdate.bat`をダブルクリックし、画面で旧フォルダーを選びます。PowerShellのコマンドを手入力する必要はありません。準備ツールは独立した更新環境で新版本体・専用Python環境・必要な実行環境を準備し、起動確認と切替を行います。切替が完了すると元の`Start.bat`から新版が自動起動します。確認に失敗した場合は本体の起動・更新を止めるため、表示を控えてください。
証明書検証を無効にして進めないでください。

旧版からの更新で新ZIPを旧環境へ上書きする必要はありません。設定・ルーム・会話を手作業で移し替えないでください。

独自にpipを導入して使っている場合はpip自身にも修正版が必要です。OSやブラウザの更新だけで、Pythonが独自に持つ証明書まで更新されるとは限りません。WSL・ソース版では起動前に修正版uvを用意し、同じソースの固定依存で環境を同期してください。

## 今回の安全対策と残る注意

今回の更新には、Python・ブラウザ用Node・通信ライブラリと証明書・更新時のデータ保護の対策を含みます。一方、画像処理用のPillowと、Liteの準備用実行環境に内蔵された一部のBrotliには、未対応の既知問題が残っています。Python用Brotli単体の更新は、別のライブラリに内蔵されたコピーの更新にはなりません。

当面、入手元の分からない画像やフォントをNexus Arkで読み込まないでください。Liteの準備はアプリ内の案内から進め、同梱環境を使った`wrangler dev`やMiniflareなどのローカル開発実行は行わないでください。通常の準備経路にも未検証の例外処理があるため、これらの注意だけで未対応問題が解消したとは扱いません。

互換性のある公式修正版と実物の検証を後続対応として管理しています。独自にPillowの依存制約を外したり、同梱バイナリを差し替えたりせず、対応状況は今後の配布案内で確認してください。
